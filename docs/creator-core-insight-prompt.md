# Creator core insight Prompt comparison

## Scope

Base: `51293c4a6f33588c670fcabb9cfc69eac8f88317`.
This candidate changes only Creator Prompt text in `creator_clone.py`.
It does not incorporate PR #29. UI, renderer, schema, normalization, classification,
client, settings, evidence preparation and fallbacks remain unchanged.

The existing shared `content_profile_prompt_text` now asks for concrete positioning,
a judgment-first summary, understandable traits, and actionable methods. Positioning
and summary remain distinct, visible expressions, not mutually exclusive fields.
Observations, interpretations and future suggestions must be distinguished.
Existing forced minimum counts in micro/reduce/final instructions were relaxed to
prefer informative conclusions rather than filler. No new output fields were added.

| Existing instruction | Candidate intent |
| --- | --- |
| Summary explains what drives growth | Explain concrete content methods and the next worthwhile experiment |
| Type-specific guidance alone | Also explain the account's specific object, presentation and distinctive methods |
| Several modules request minimum item counts | Prefer fewer informative methods without generic padding |
| Abstract effectiveness language | Separate observed facts, plausible explanations and proposed actions |

## Actual call path

Five selected samples use `distill_creator_clone` -> local Map summaries ->
`build_micro_reduce_distill_prompt` -> the existing provider/execution layer.
The shared fragment is also included once by normal, lite, reduce and final-reduce
builders. The micro path submits no direct images; this work does not change its
existing text compression or claim that archived evidence was all sent to the model.

## Private real comparison

The baseline is the real report generated by the user after restoring main, not
the September C report or a synthetic fixture. Both previews use main's original
renderer and CSS. The same five selected samples and copied material were used.
The historical Creator memory context had changed after the baseline generation:
this is a same-material comparison, not a fully controlled input experiment.

The saved baseline Prompt had 5,030 characters. Reconstructing main with the frozen
current context produced 5,059; the candidate produced 5,712. The difference between
historical and reconstructed main was in memory context. Full private Prompts,
reports, responses and screenshots are deliberately not committed.

One newly authorized task-level generation completed in 117.04 seconds:
one logical request, one HTTP attempt, HTTP 200, model status `completed`,
no retry or fallback. Provider/model: `openai_responses` / `gpt-5.6`.
Temperature 0.2 and `max_output_tokens=1800` were retained.
Only the isolated acceptance process used a 300-second request ceiling and
360-second Quick task budget; the real main settings were not changed.
The provider received 300 seconds. The gateway reported 2,701 input and 3,512 output
tokens (6,213 total); its output count exceeds the requested cap, a gateway-reporting
or enforcement question not investigated or changed in this Prompt experiment.

## Result: no clear overall gain

- The candidate positioning is more specific about presentation variants, but also
  longer. The original was already more specific than a broad category label.
- The candidate summary brings a concrete title-comparison experiment forward.
  However, it turns a high-interaction sample into an overly certain explanation
  of sharing/revisiting value. The original also contained inferential claims, but
  retained a clearer limitation in its opening summary.
- The baseline already had executable formulas. The candidate reorganizes and
  prioritizes them; this is not evidence of a general increase in analytical depth.
- Important evidence gaps remain in the candidate. No direct visual input was sent;
  detailed camera, lighting and editing statements should be read as proposals,
  not verified observations. Some phrasing still blurs that distinction.
- The raw model summary is preserved by the existing result preparation; no local
  substitution was found for that field. Existing synthesized strategy lists and
  display truncation remain unchanged, and are not improvements from this patch.

The 1280px preview retains the prominent summary, positioning and two-column flow.
At 390px both original and candidate inherit the old narrow title column and dense
two-column layout. There is no document-level horizontal overflow, but this is not
a mobile readability pass. No CSS was changed to hide this existing limitation.
Static report comparison is not a test of the full web generation interaction.
User product judgment remains pending; no second generation is authorized here.
