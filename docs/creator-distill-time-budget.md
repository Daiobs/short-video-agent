# Creator Distill Time Budget

## 目标

创作者蒸馏使用同一个单调时钟 deadline 贯穿业务层、执行层和 LLM Provider。任何兼容请求或精简重试只能消费剩余预算，不能重新获得完整 timeout。

## 请求上限

- 成功路径：1 个逻辑请求，通常 1 个 HTTP 请求。
- `response_format` 明确不兼容：同一逻辑请求最多 2 个 HTTP 请求。
- 精简重试路径：最多 2 个逻辑请求；两次逻辑请求及其 HTTP 请求共享同一 deadline。
- 429、401/403、明确额度不足：1 个逻辑请求，立即停止。

旧路径可能形成“外层重试 × 执行层 schema 重试 × Provider 兼容回退”的请求放大。当前网页蒸馏将执行层固定为一次尝试，外层只对白名单错误执行一次精简重试。

## 自动预算与人工覆盖

PR #21 之前（`442c7045`），计划按任务规模计算单批/最终汇总等待额度，并将单批推荐值传给 Provider。PR #21（`187620a`）将推荐值替换为显式固定配置，并在首次请求前预扣重试时间。本轮保留其错误分类和有界重试，但调整固定等待策略，不再承诺 PR #21 的数值不变。

`creator_distill_budget_mode` 默认为 `auto`。`creator_distill_request_timeout_seconds` 在自动模式是基础下限，在 `manual` 模式才是用户选择的请求上限。Final Reduce 等待值使用同样的模式语义。普通单作品与 Execution Pack 不启用 Creator 的动态请求预算。

| 设置 | 新默认 | 合法最大值 |
| --- | ---: | ---: |
| 普通分析单次请求（不变） | 90 秒 | 300 秒 |
| Creator 基础等待值 / 人工请求上限 | 180 秒 | 1200 秒 |
| Quick 整任务上限 | 1800 秒 | 14400 秒 |
| Deep 整任务上限 | 3600 秒 | 14400 秒 |
| Batch 整任务上限 | 7200 秒 | 14400 秒 |
| Final Reduce 基础等待值 / 人工请求上限 | 600 秒 | 2400 秒 |
| Final Reduce 最低预留 | 120 秒 | 600 秒 |
| 紧凑重试最低剩余 | 60 秒 | 300 秒 |

自动单批请求额度取基础值与下式的较大者，再限制到 1200 秒并取整：

```text
180 + 批内样本数 * 20 + 实际 Prompt 字符数 / 1000 * 8
    + 有界的视频时长辅助项
```

时长辅助项采用已有的对数增长规则，单批最多贡献 180 秒。最终汇总按 `300 + 批次数*75 + Prompt复杂度 + 样本复杂度 + 有界时长项` 与基础值取较大值，最多 2400 秒。视频时长只是辅助线索，不代表模型逐秒观看完整视频；所有额度都不是 ETA。

普通 Creator 的自动任务预算为 `min(用户整任务上限, 请求额度*2+30)`；这为允许的紧凑重试留有空间，但不从首次请求预扣 60 秒。五条样本、8215 字符、无时长数据时，请求额度为 **345 秒**，默认任务预算为 **720 秒**。Provider 接收相同额度，不再被 180/240 秒二次截断。

人工模式直接使用明确请求额度和任务上限。自动普通请求的完整计划额度无法容纳于任务剩余时间时，明确停止且不发送请求；不静默缩短后宣称执行了完整自动计划。

旧本地设置未记录模式且总预算恰为旧默认 Quick 240 / Deep 600 / Batch 600 秒时，只在读取时采用新默认值，不改写文件。显式模式、非默认旧值及环境覆盖保留。历史数据无法区分“当年主动选择的默认值”与“自动保存的默认值”；需要保留这些数值的用户应明确选择人工模式或重新保存任务上限。

Quick timeout 不自动重发。Deep timeout 仅按原白名单和实际剩余预算允许一次紧凑重试；无效 JSON、502/503 等仍受原策略控制。更长等待不增加请求层级或调用次数。

## 本地截止的实际范围

Creator 的请求使用短连接/池等待（最多 10 秒）、短发送等待（最多 30 秒）及有效请求额度作为读取等待。另以同一剩余额度包围完整异步 HTTP 交换，达到截止时取消当前本地请求并关闭客户端；兼容回退共享原 child deadline，不启动遗留后台线程。

这不是把 HTTPX read timeout 当作整任务硬取消：网络交换有实际取消，业务阶段仍通过单调 deadline 检查；同步 Prompt 构造、JSON 校验和文件写入不被强制抢占。因此整任务额度是模型等待及阶段准入上限，不保证整个 Python 函数恰好在该秒退出。本地取消无法证明上游已取消或 usage 为零。

页面展示模式、样本数、当前实际请求上限、任务上限、已等待时间和等待响应状态，不用推荐额度冒充实际额度。旧 30 分钟 stale 规则对合法 Creator 预算窗口作有界例外；截止失效后恢复原规则。当前没有 worker lease/heartbeat，未到截止只表示仍在允许等待窗口内，不证明 worker 存活。

## 错误语义

- `LLM_RATE_LIMITED`：429，不重试。
- `LLM_AUTH_FAILED`：401/403，不重试。
- `LLM_QUOTA_EXCEEDED`：明确余额或配额不足，不重试。
- `LLM_GATEWAY_TIMEOUT`：408、504、客户端 timeout 或 deadline 耗尽。
- `LLM_UPSTREAM_UNAVAILABLE`：502、503 或传输错误。
- `LLM_RESPONSE_INVALID`：响应不是合法 JSON。

公开诊断只包含状态码、Provider、阶段、逻辑/HTTP 尝试次数、是否允许重试和是否使用 `response_format` 回退。不得包含 Key、Authorization、Prompt、网关正文或本机路径。

## Batch 行为

每批开始前重新计算：

```text
可供批次使用的预算 = 共享任务剩余预算 - Final Reduce 预留
本批预算 = min(按本批实际 Prompt 计算的请求额度, 可用预算 / 剩余批次数)
```

自动 Batch 任务预算为各批计划额度之和加最终汇总预留及 30 秒，但不超过用户整任务上限。Final Reduce 先依据来源摘要估算，至少保留配置的最低预留；实际最终 Prompt 构造后重新计算请求额度，并受同一剩余时间约束。各批不重置总 deadline。

因总上限压缩批次或最终汇总额度时，记录 `budget_limited`、实际额度和警告。预算不足时停止创建新请求，保留已成功批次及已有主报告；本地汇总仍标为 fallback，不覆盖已有主报告。Manifest 使用 `completed`、`partial`、`budget_exhausted`、`rate_limited` 或 `auth_failed` 表达最终状态。

## 验证边界

测试使用 fake Provider、fake monotonic clock 和 HTTPX MockTransport。覆盖 281 秒虚拟耗时在 345 秒请求预算内一次完成、响应头/正文阻塞的本地取消及客户端关闭、设置原子校验、分批共享预算和长任务 stale。取消测试只有亚秒级本地等待，不真实 sleep 数分钟，也不调用模型。本轮未获得第三次真实生成授权：

```text
LIVE_LLM_SMOKE_NOT_RUN
```
