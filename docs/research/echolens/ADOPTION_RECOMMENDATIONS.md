# 采纳建议与落地优先级

## 决策原则

只采纳符合以下条件的能力：

1. 改善短视频拆解第一版的可理解性或恢复能力。
2. 不引入远端敏感凭证托管。
3. 不削弱 Case、Job、Evidence、Report 等真源。
4. 所有分析、同步和生成仍由用户明确确认。
5. 可以用现有接口和产物完成时，不新增数据库、队列或 Provider。

## R-01：单作品四阶段状态条

- **分类**：`ADOPT-NOW`
- **对应用户问题**：用户无法快速判断当前完成到“链接、素材、证据、分析”的哪一步，也不知道部分失败后哪些结果还可用。
- **EchoLens 的实现表现**：同一页面先显示作品元数据和媒体，再显示转录/模型区域，信息顺序清楚；但失败、处理中和可点击按钮同时出现。[E-003][E-008]
- **我们当前缺口**：`short-video-agent` 有更完整的 Job/Case 状态和恢复合同，但单作品页的信息密度高，用户需要理解多个后台名词。
- **推荐落地项目**：`short-video-agent`。
- **优先级**：`P0`。
- **实现成本**：`S`，预计 1–2 个前端工作日；优先复用现有 DTO，不改后端。
- **风险**：错误地把派生 UI 状态当成真源；必须只读映射既有 Job/Case。
- **依赖**：现有 Job 状态、Case readiness、ASR/OCR 和 AI 分析状态。
- **最小可用版本**：四个固定阶段卡：链接检测、媒体素材、证据富化、AI 拆解；每卡显示 `未开始/运行中/部分完成/成功/失败` 和可用结果数。
- **验收标准**：刷新前后状态一致；任何阶段失败不隐藏前序结果；页面加载不创建 Job；恢复入口保持人工确认；现有测试和安全合同不回归。

## R-02：证据产物就地动作条

- **分类**：`ADOPT-NOW`
- **对应用户问题**：用户已生成视频、contact sheet、ASR、OCR 和 Prompt，却要在高级区或多个页面寻找打开、复制和下载入口。
- **EchoLens 的实现表现**：封面、视频、音频、标题、作者和作品链接旁都放置预览、试听、下载或复制动作，反馈路径短。[E-003]
- **我们当前缺口**：已有安全路由和产物，但动作样式和层级不统一。
- **推荐落地项目**：`short-video-agent` 的 Case 详情页；作为安全动作组件也可供 `xingkong-workbench-secure` 复用。
- **优先级**：`P0`。
- **实现成本**：`S`，2–3 个前端工作日。
- **风险**：把本机绝对路径、签名媒体 URL 或敏感文本暴露到 DOM/剪贴板。
- **依赖**：现有 Case 安全文件路由和字段净化函数。
- **最小可用版本**：只支持已有同源安全路由；视频/图片打开，ASR/OCR/Prompt 复制，允许文件下载；不新增 ZIP。
- **验收标准**：动作只在产物存在时出现；复制内容无 Cookie、Token、路径和外部签名 URL；移动端可用；失败时给出可恢复提示；不触发分析或外部请求。

## R-03：部分失败摘要与下一步

- **分类**：`ADOPT-NOW`
- **对应用户问题**：一个 Provider 失败时，用户不知道整个任务是否失败、是否应该等待、是否要重跑全部步骤。
- **EchoLens 的实现表现**：能显示 `DashScope ASR` 的具体失败文本，但同时保留“处理中”和“获取结果”，终态冲突。[E-008]
- **我们当前缺口**：现有后端恢复信息完整，但页面可以进一步压缩成“失败步骤 / 已有结果 / 建议动作”三行摘要。
- **推荐落地项目**：共同基础设施，先落 `short-video-agent`。
- **优先级**：`P0`。
- **实现成本**：`S`，1–2 个工作日。
- **风险**：把建议动作写成自动修复，或把 stale 错标为 failed。
- **依赖**：`error_code`、`last_completed_stage`、`available_results`、`recovery_hint`、`resume_target`。
- **最小可用版本**：只读错误摘要组件，最多一个主动作和一个“查看详情”。
- **验收标准**：`stale` 不回写状态；恢复只打开正确步骤；没有安全目标时不显示伪按钮；已有 Case/证据始终保留；所有错误文案经过敏感信息净化。

## R-04：来源型收藏/关注工作区

- **分类**：`ADOPT-LATER`
- **对应用户问题**：用户希望从已授权的收藏或关注对象中筛选值得分析的内容，而不是逐条复制链接。
- **EchoLens 的实现表现**：收藏页有搜索、关注状态、发布时间、计数、分页/虚拟滚动；关注页有账号搜索和刷新。[E-006][E-007]
- **我们当前缺口**：`short-video-agent` 有素材池和资产库，但没有一个经过最小权限设计的“平台收藏/关注只读来源”。
- **推荐落地项目**：`xingkong-workbench-secure` 的本机连接器层，输出净化 handoff；`short-video-agent` 只消费 handoff。
- **优先级**：`P2`。
- **实现成本**：`L`。
- **风险**：平台条款、登录态、私人数据、全量同步、误把关注关系当成公共数据。
- **依赖**：本机连接器威胁模型、用户确认、字段允许列表、来源审计、删除/撤销合同。
- **最小可用版本**：用户在本机明确选择少量公开作品，连接器仅输出作品 ID、标题、作者和可见指标，不输出 Cookie、请求头、签名 URL或完整关系图。
- **验收标准**：远端服务从不接收 Cookie；每次采集显示范围并确认；不自动刷新；可导出审计清单；停止条件覆盖验证码、风控和权限变化。

## R-05：轻量可搜索最近历史

- **分类**：`NEEDS-VALIDATION`
- **对应用户问题**：用户想快速回到最近一个结果，不想进入完整资产库。
- **EchoLens 的实现表现**：首页侧栏有最近记录和历史搜索，当前为空。[E-003]
- **我们当前缺口**：现有 Workbench Overview 和 Library 已覆盖最近结果与搜索，新增侧栏可能重复信息架构。
- **推荐落地项目**：`short-video-agent` Workbench Shell。
- **优先级**：`P1`，先做用户验证。
- **实现成本**：`S–M`。
- **风险**：建立第二历史真源、挤压主流程、移动端侧栏复杂化。
- **依赖**：只读 Overview/Library DTO。
- **最小可用版本**：只显示最近 5 条已存在资产和一个搜索入口；不单独保存历史。
- **验收标准**：数据完全来自现有真源；删除缓存不丢数据；页面不读取报告正文；用户测试证明比现有入口更快。

## R-06：ITN 与推理模式的显式成本控制

- **分类**：`NEEDS-VALIDATION`
- **对应用户问题**：用户可能需要在口语原文、规范数字文本、快速结果和深度结果之间选择。
- **EchoLens 的实现表现**：提供“逆文本规范化”“思考/深入推理”和 `E1` 模型控件，但不显示成本、延迟或版本。[E-003]
- **我们当前缺口**：ASR/LLM 配置分散在 Provider 设置，普通用户不一定理解参数影响。
- **推荐落地项目**：`short-video-agent` 设置与单次任务确认层。
- **优先级**：`P2`。
- **实现成本**：`M`。
- **风险**：把底层参数暴露成复杂 UI；用户误以为“思考”一定更准确。
- **依赖**：真实 Provider 支持、成本估算、输出版本化。
- **最小可用版本**：仅在 Provider 明确支持时提供“标准转写/保留口语”与“快速/深度”两个解释清楚的选项，并显示预计成本范围。
- **验收标准**：选项进入任务审计；结果保存参数和模型版本；不支持时不展示；无自动升级到高成本模式。

## R-07：移动端紧凑结果卡

- **分类**：`ADOPT-LATER`
- **对应用户问题**：内容运营可能在手机上查看进度和复制结果。
- **EchoLens 的实现表现**：DOM 使用 `100dvh` 等移动友好类，但本轮没有实际移动视口验证。
- **我们当前缺口**：当前仓库已有 390px 回归，复杂 Case 结果仍可能需要进一步操作优化。
- **推荐落地项目**：两个方向的共用前端设计系统。
- **优先级**：`P2`。
- **实现成本**：`M`。
- **风险**：为小屏隐藏证据或确认信息。
- **依赖**：R-01/R-02 组件稳定、真实手机测试。
- **最小可用版本**：手机端只折叠，不删除证据；主动作保持可见；表格转卡片。
- **验收标准**：390px 无页面横向溢出；键盘和触控可用；安全确认不被折叠；桌面行为不回归。

## R-08：远端保存完整抖音 Cookie

- **分类**：`DO-NOT-ADOPT`
- **对应用户问题**：想自动读取本人收藏和关注。
- **EchoLens 的实现表现**：要求粘贴完整 Cookie，验证并保存；法律声明称加密。[E-004][E-005]
- **我们当前缺口**：不是缺口；现有边界刻意避免公开服务托管隐式登录态。
- **推荐落地项目**：不落地；若未来需要，进入 `xingkong-workbench-secure` 本机连接器研究。
- **优先级**：不排期。
- **实现成本**：`XL`，且长期安全成本高。
- **风险**：账号接管、平台违规、租户隔离、泄露、撤销和合规责任。
- **依赖**：不应为当前阶段建立。
- **最小可用版本**：无；替代方案是本机可见 DOM 或用户选择的净化 handoff。
- **验收标准**：任何方案都必须证明服务端不接收 Cookie；否则不通过。

## R-09：自动读取剪贴板并预填

- **分类**：`DO-NOT-ADOPT`
- **对应用户问题**：减少粘贴一步。
- **EchoLens 的实现表现**：页面声明检测剪贴板最新记录中的抖音链接并自动填入。[E-003]
- **我们当前缺口**：不是关键摩擦；显式粘贴已经足够。
- **推荐落地项目**：不落地。
- **优先级**：不排期。
- **实现成本**：`S`，但隐私收益为负。
- **风险**：意外读取私人链接、用户误解、浏览器权限和审计困难。
- **依赖**：无。
- **最小可用版本**：替代为用户点击“从剪贴板粘贴”，并在动作时明确授权。
- **验收标准**：页面加载绝不主动读取剪贴板；只有用户手势触发一次性读取。

## R-10：无证据和无版本的 AI 结果

- **分类**：`DO-NOT-ADOPT`
- **对应用户问题**：希望快速获得看似完整的结论。
- **EchoLens 的实现表现**：模型别名和推理控件可见，但成功结果、来源映射、版本和生成时间未观察。[E-008]
- **我们当前缺口**：当前项目已经建立证据缺口、质量校准和报告质量，不应为简洁而去掉。
- **推荐落地项目**：不落地；反向作为质量门禁。
- **优先级**：持续门禁。
- **实现成本**：维持现有能力为 `M`；去掉能力虽然便宜但不允许。
- **风险**：幻觉、不可复核、旧结果误用、错误创作决策。
- **依赖**：Evidence Schema、报告版本、质量评分和人工验收。
- **最小可用版本**：每条关键结论至少有证据类型、定位、置信度；缺失时标成假设。
- **验收标准**：事实/推断/建议分层；保存 provider/model/time/input version；没有证据的高置信结论被测试拒绝。

## 优先级汇总

| 优先级 | 建议 | 目标项目 |
| --- | --- | --- |
| P0 | R-01 四阶段状态条 | short-video-agent |
| P0 | R-02 证据产物就地动作条 | short-video-agent / 共用组件 |
| P0 | R-03 部分失败摘要 | 共用基础设施 |
| P1 | R-05 轻量历史（先验证） | short-video-agent |
| P2 | R-04 本机来源工作区 | xingkong-workbench-secure → handoff |
| P2 | R-06 显式成本模式 | short-video-agent |
| P2 | R-07 移动端紧凑卡 | 共用设计系统 |
| 不排期 | R-08/R-09/R-10 | 禁止或质量门禁 |

## 下一项最小实施任务建议

在用户审阅本研究后，新建独立任务：

```text
为 short-video-agent 单作品页增加只读“四阶段状态条 + 部分失败摘要”，
仅映射现有 Job/Case readiness，不新增接口、数据库、Provider 或自动重试。
```

建议验收范围：桌面与 390px、空/运行/部分成功/失败/成功五种 fixture、敏感字段净化、刷新一致、零外部调用、`git diff --check` 和现有完整测试。
