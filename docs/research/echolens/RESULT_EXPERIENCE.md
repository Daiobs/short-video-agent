# 分析结果体验

## 本次实际看到的结果

当前首页保留了一条已检测作品，显示：

- 作品类型。
- 作者和标准抖音作品链接。
- 封面、视频、音频及其预览/试听和下载。
- 标题。
- 可复制的作者、链接、标题和类型。
- ASR 提供方错误。
- “转录任务处理中”的状态文案。
- 逆文本规范化、深入推理、`E1` 模型和“获取结果”控件。[E-003][E-008]

为避免提交新任务或产生付费调用，本轮未点击“获取结果”。因此不能把页面上存在模型控件等同于已经观察到高质量 AI 分析。

## 事实、证据与推断

当前结果区把作品元数据和媒体放在前面，这是一个好的“事实层”。问题在于后续模型区域没有可见的合同说明：

- 哪些字段来自抖音页面。
- 哪些来自 ASR。
- 哪些是模型推断。
- 哪些是行动建议。
- ASR 失败后模型是否会在无字幕条件下继续生成。

在已有样本中，ASR 返回“无有效片段”类失败。如果系统仍允许模型生成而不显式降级，就可能把缺少语音证据的作品误写成有口播结构。EchoLens 是否实际这样做没有证据，故只能标为风险假设，不能写成已发生问题。

## 结果是否可用于下一步行动

### 已证明可行动

- 预览和下载封面、视频、音频。
- 复制标题、作者和作品链接。
- 在收藏/关注工作区搜索或筛选（数据链路未配置，但 UI 已存在）。

### 未证明可行动

- 解释为什么作品表现好。
- 形成可复用爆款规律。
- 生成下一条可拍脚本、镜头、标题或选题。
- 把结论回链到时间码、字幕或关键帧。
- 对比多个作品并筛选代表样本。
- 把结果保存成版本化报告或校准样本。

结论：EchoLens 的“数据和媒体结果”能直接行动；“AI 分析结果”在本轮不能判定。

## 成功、部分成功与失败的表达

当前样本属于部分成功：媒体和元数据已存在，ASR 失败。页面没有因为 ASR 失败清空已有结果，这一点值得借鉴。需要改进的是把状态拆开：

```text
链接解析：成功
媒体获取：成功
ASR：失败（错误码与建议）
AI 结果：未开始 / 被阻断 / 可在确认后继续
```

而不是同时显示失败、处理中和可提交按钮。

## 对现有项目的直接启示

`short-video-agent` 应保留自身更强的证据结构，同时借鉴 EchoLens 的结果就地动作：

1. Case 顶部先展示“原始事实与可用素材”。
2. 明确分离“事实”“模型推断”“创作建议”。
3. 每条结论显示证据来源：视频时间码、关键帧、ASR、OCR、评论或指标。
4. 部分失败不清空 Case；只对失败步骤提供人工重跑。
5. 显示模型提供方/模型名、生成时间、输入证据版本和质量状态。
6. 缺证据时降级成“待验证假设”，不要输出假高置信策略。

## 幻觉与证据风险

| 风险 | EchoLens 当前证据 | 建议 |
| --- | --- | --- |
| ASR 失败后仍生成文本 | 页面按钮仍可用；是否会生成未知 | 失败步骤显式阻断或降级 |
| 模型别名不可追踪 | 只显示 `E1` | 保存 provider/model/version |
| 原视频存在但结论不引用 | 媒体可预览，未见时间码引用 | 结论必须绑定证据定位 |
| 用户无法区分事实与建议 | 未见分层 | 三层结果 Schema |
| 旧结果失效不可见 | 未见生成时间/输入版本 | 记录来源版本和陈旧状态 |

## 最终评价

文字是否丰富在本次样本中无法评价；结果能否支持下一步行动的结论是：**媒体层可以，分析层未证明，证据层明显不足。** 这也是 EchoLens 不应成为 `short-video-agent` 长期分析质量基准的主要原因。
